## Implementation Steps

### Phase 1: Install sauce-api-mcp Package (System-Wide)

**Action**: Install globally for both LLM clients to access

```bash
# Ensure pip is up to date
pip install --upgrade pip

# Install sauce-api-mcp package (includes both servers)
pip install sauce-api-mcp

# Verify installation
which sauce-api-mcp
which sauce-api-mcp-rdc
# Expected: /usr/local/bin/sauce-api-mcp and /usr/local/bin/sauce-api-mcp-rdc
# Or if using --user: ~/.local/bin/sauce-api-mcp

# Quick sanity check (both will print error about interactive mode - that's expected)
sauce-api-mcp --help 2>&1 | head -5
sauce-api-mcp-rdc --help 2>&1 | head -5
```

**If permission denied**:
```bash
# Option A: Use user install (no sudo needed)
pip install --user sauce-api-mcp

# Option B: Use sudo (if system Python)
sudo pip install sauce-api-mcp
```

**What gets installed**:
- `sauce-api-mcp` - Core server (account, devices, jobs, builds, storage, tunnels)
- `sauce-api-mcp-rdc` - RDC-focused server with OpenAPI schema discovery

### Phase 5: Visualization & Sharing with Sauce Insights

Sauce Labs provides native **Insights** dashboards with built-in sharing capabilities. No additional infrastructure needed.

#### What is Sauce Insights?

Insights is the built-in analytics and reporting hub that provides:
- **Test Overview Dashboard**: Pass/fail rates, test trends, platform coverage
- **Error Analysis**: Failure patterns, ML-driven root cause suggestions
- **Activity Tracking**: Team/org-level test execution metrics
- **Test Case Health**: Historical performance, flaky test detection
- **Build Trends**: Compare test runs across builds

All data is automatically populated from your Sauce Labs test jobs—no additional configuration needed beyond running tests.

#### Setup (User-Level)

End users access Insights directly:

1. Log into Sauce Labs: https://app.saucelabs.com
2. Click **Insights** in the left navigation panel
3. Configure filters:
   - **Source**: Select `Real Devices` (for RDC Android tests) or `Virtual Devices` (for web tests)
   - **Build**: Filter by build name (matches `SAUCE_BUILD_NAME` in test configs)
   - **Date Range**: Last 7 days, 30 days, custom
4. Explore dashboards:
   - **Overview**: High-level metrics (pass rate, total jobs, coverage)
   - **Errors**: Failure breakdown by error type, stack trace, affected devices
   - **Test Cases**: Individual test performance, trend lines, flaky detection

#### Sharing Insights with Teams

Sauce Labs supports built-in sharing based on org/team permissions:

- **Team Dashboards**: Insights views are visible to all org members
- **Role-Based Access**: Admin, Member, Read-Only roles control visibility
- **Direct Links**: Copy URL of any filtered Insights view to share (requires Sauce Labs account)
- **Scheduled Reports** (if available): Email snapshots of dashboards on a schedule

For the Dream Demo, note: *"All test results automatically appear in Sauce Insights—the native analytics platform included with Sauce Labs."*

#### Key Metrics to Highlight

Showcase these pre-built Insights views:

| Metric | Where to Find It | Why It Matters |
|--------|------------------|----------------|
| Pass/Fail Rate | Insights → Overview | Quality gate |
| Test Duration Trends | Insights → Test Cases → Duration | Performance regression |
| Device Coverage | Insights → Overview → Platforms | Test breadth |
| Flaky Tests | Insights → Errors → ML Insights | Test reliability |
| Build Success Trend | Insights → Overview → Jobs over time | CI/CD health |
| RDC Job Status | Insights → Overview → Filter by Real Devices | Mobile test health |

## Dependencies & Risks

### Dependencies
- Python 3.10+ (already present in project)
- `pip` package manager
- Sauce Labs account with API access (already used)
- MCP-compatible LLM client (Claude Desktop, Gemini CLI installed)

### Risks
- **Path issues**: MCP clients require absolute paths to executables
- **Environment mismatch**: MCP client may use different Python than where package installed
- **Credential leakage**: Avoid hardcoding secrets in config files; use env vars
- **Region mismatch**: Default is us-west-1; ensure matches `.sauce/config.yml`
